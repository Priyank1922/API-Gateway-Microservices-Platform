📘 Complete Guide: API Gateway & Microservices Platform
🌟 1. Why Does This System Exist & How Does It Work?
The Real-World Analogy: An International Airport 🛫
Imagine a large international airport:

The API Gateway (Port 8080) is the Main Entrance & Security Checkpoint. Every visitor enters here. It inspects passports (JWT tokens), limits overcrowding (Rate Limiter), catches bad actors (AI Threat Defense), and directs passengers to their terminal.
Eureka Server (Port 8761) is the Airport Information Display Board. When a terminal or shop opens, it registers its location so the security guards know where to direct traffic.
Auth Service (Port 8081) is the Passport & ID Office. It registers users and issues cryptographic JWT passes.
Product Service (Port 8082) is the Duty-Free Catalog & Warehouse. It tracks items and stock counts.
Order Service (Port 8083) is the Cashier & Billing Desk. It creates receipts and processes payments.
AI Analytics Service (Port 8084) is the Airport Radar & AI Surveillance Center. It calculates risk scores for suspicious behavior and forecasts traffic load.

⚡ 2. How to Launch the Entire System
Step 1: Ensure MySQL is Running
Make sure your local MySQL server is running on localhost:3306 with credentials root / root (or the credentials defined in each service's application.properties). The databases will be created automatically on startup.

Step 2: Build All Modules
Open PowerShell in c:\Desktop\API_GateWay and run:

powershell
.\build.bat
(Or via Maven: mvn clean package -DskipTests)

Step 3: Start All 6 Services in Separate Windows
Run:

powershell
.\start-all.bat
This opens 6 dedicated terminal windows in sequence:

Eureka Server on Port 8761
Auth Service on Port 8081
Product Service on Port 8082
Order Service on Port 8083
AI Analytics Service on Port 8084
API Gateway on Port 8080
To stop all services anytime, run 

stop-all.bat
.

🖥️ 3. How to Operate the Web Dashboard
Open your browser and navigate to: http://localhost:8080/

The dashboard consists of 5 interactive sections in the top navigation bar:

1️⃣ Overview (http://localhost:8080/)
Live KPI Cards: Uptime, Total Requests routed through the gateway, Rate Limited (429) count, and Eureka node status.
Microservices Health Grid: Real-time status cards for all 5 services with live ping indicators (UP / DOWN).
Route Table: Shows all active Spring Cloud Gateway route paths (/api/auth/**, /api/products/**, /api/orders/**, /api/ai/**).
2️⃣ API Sandbox (http://localhost:8080/sandbox)
Preset Chips: Click chips like POST /api/auth/login, GET /api/products, or POST /api/orders to instantly populate the method, endpoint, and JSON payload.
Send Request Button: Fires the request through the Gateway filter pipeline and displays:
Status Code (e.g. 200 OK, 401 Unauthorized, 429 Too Many Requests)
Latency & Trace ID (X-Correlation-Id)
Formatted JSON Response
Auto-Token Capture: When you execute POST /api/auth/login, the gateway automatically extracts the JWT token and places it into the Authorization input field for subsequent requests!
3️⃣ Resilience & Rate Limiting Lab (http://localhost:8080/resilience)
Burst Simulator: Click "Launch 25-Request Burst" or "Launch 40-Request Overload".
Watch the live event log stream as the first ~15-20 requests succeed (200 OK) and the excess burst requests are throttled with HTTP 429 Too Many Requests.
Circuit Breaker Fallbacks: Click "Test Fallback" buttons to verify that if a microservice is offline, the gateway returns a safe fallback payload instead of crashing.
4️⃣ AI Security Radar (http://localhost:8080/security)
Payload Inspector: Click sample attack buttons (SQL Injection, XSS Attack, Path Traversal) and hit "Analyze Payload with AI Engine" to see live threat scores (0–100) and recommendation actions (BLOCK vs ALLOW).
Live Threat Stream Table: Displays quarantined malicious requests with client IP, detected threat classification, and timestamp.
5️⃣ API Documentation (http://localhost:8080/docs)
Full OpenAPI catalog describing all endpoints, HTTP methods, required headers, and parameters.
